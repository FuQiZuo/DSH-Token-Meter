**Token Meter** — a token-usage tracking plugin for DeepSeek Harness (DSH).

A floating panel mounted over `shell.overlay` in the bottom-right corner. It shows both the **current session** (input / output / cache hit / cache miss / total) and **all sessions** (cumulative input / cumulative output / cumulative hit / cumulative miss). Pure client-side plugin: it does not modify application code — it only registers one panel and one settings page.

## Quick start

```bash
dsh plugin --profile web add github:FuQiZuo/DSH-Token-Meter
```

Restart (or reload) the web profile to take effect. The panel appears in the bottom-right corner; tune statistics mode, language, transparency, and text size in **Settings › Token Meter settings**.

Uninstall:

```bash
dsh plugin --profile web rm dsh-token-meter
```

### Install locally (without GitHub)

Run this in the plugin repository root:

```bash
dsh plugin --profile web add link:.
```

> `link:.` points to the current directory. Run it at the plugin repository root, not `link:.\some-subdir`.

### Try it once (no install, as a dynamic Cordis plugin)

1. Copy the `apply(ctx) { ... }` body out of `client.js`;
2. Use `cordis_define` to create a plugin and paste it as **Client code** (`return { apply(ctx) { ... } }`), then activate with `cordis_run`;
3. Refresh the page to take effect; stop the plugin on the Run card to fully unload it (panel and settings page are torn down automatically).

`client.js` depends on the DSH Client runtime `slots`, `locale`, and `sessions` services and cannot run in a plain browser.

## Features

| Feature | Description |
| --- | --- |
| Current session | input / output / cache hit / cache miss / total |
| All sessions | cumulative input / cumulative output / cumulative hit / cumulative miss |
| Live / deferred mode | In live mode the local tokeniser (`gpt-tokenizer` p50k_base) counts the streamed output every second; input is only added while the model is thinking (reasoning blocks). When the request finishes the value is calibrated to the real `tokenUsage` projection |
| Smooth climb | Output tokens are counted from the real streamed output blocks by the built-in tokeniser, so they climb only while content is actually being generated (flat while thinking or idle); input climbs at the measured 2400–2800 tokens/second throughput while thinking, to avoid large jumps |
| Calibration transition | After the request ends and the real value replaces the estimate, the number stays orange for about 1 second before turning white, so the hand-off is visible |
| Settings page | Statistics mode (live / deferred), language (zh / en), panel transparency (0–100% slider — only the background and frosted blur fade; the border stays fixed), text size (small / medium / large). Persisted via localStorage, copy follows the language setting |
| Disclaimer | The ⓘ in settings opens a centered disclaimer modal; click the backdrop or × to dismiss |

## Data source and buckets

- All totals read DSH's `tokenUsage` projection (client-authoritative): `input = uncachedInputTokens + cacheReadTokens + cacheWriteTokens`, `hit = cacheReadTokens`, `miss = uncachedInputTokens + cacheWriteTokens`, `total = input + output`. The four buckets are disjoint.
- The live estimate is preview-only and never participates in any limit or billing; it is calibrated to the real projection when the request finishes.
- Counted with the local tokeniser, which is not identical to DeepSeek's official tokeniser and may deviate (especially input tokens that include the reasoning chain). Trust the calibrated value after the request ends. The current-session total does not include subagent usage (known limitation).

## Development and maintenance

`client.js` is a prebuilt browser bundle generated by the DSH client bundle chain (`clientBundle` preset, `lightningcss` CSS Modules, `react` externalization). Changing the source requires building in a DSH checkout:

1. Put `src/` into the DSH workspace plugin package directory;
2. Run `tsc -b tsconfig.client.json && tsdown --env.DSH_BUILD_FACE client`;
3. Copy the produced `lib/client.js` back to the repository root (and re-bake the bundle id to `dsh-token-meter`).

## FAQ

- **Installed via `dsh plugin add` but the panel doesn't show?** Make sure you used the `web` profile and refreshed the page; the panel is a `shell.overlay` slot, not something that auto-opens after install.
- **Can I run `client.js` directly in Node?** No. It depends on the DSH Client runtime `slot` / `locale` / `session` services and errors outside the DSH page.
- **The live number differs from the number after the request ends?** Normal. The live value climbs from the local tokeniser and is a preview; the real `tokenUsage` projection is what calibrates after the request.
- **Do I need the host half?** No. The Token Meter is pure client-side; `index.js` is just the empty stub cordis needs for installation.
